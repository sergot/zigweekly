## Language & compiler

- [Partial operator precedence](https://ziglang.org/devlog/2026/#2026-10-24) - the compiler now rejects some mixed-operator expressions such as `x orelse y == z` until you add parentheses, closing proposal #114 from 2016 ([PR #30160](https://codeberg.org/ziglang/zig/pulls/30160)).
- [Fields at the top (#37375)](https://codeberg.org/ziglang/zig/issues/37375) - accepted: fields of structs, enums and unions would have to come before all declarations. Discussion on whether `zig fmt` or the compiler should enforce it is still going.
- [Remove `comptime` fields (#32045)](https://codeberg.org/ziglang/zig/issues/32045) - accepted proposal. Commenters are worried about what it means for `@call` with mixed comptime and runtime arguments, and discussion continues.
- [File-level namespace syntax (#37373)](https://codeberg.org/ziglang/zig/issues/37373) - accepted: a file could declare itself an `enum`, `union`, `opaque` or `packed struct` with a line like `struct;` at the top.
- [Replace `c_*` types with an `@C` builtin (#36082)](https://codeberg.org/ziglang/zig/issues/36082) - accepted proposal aims to express C ABI types without reserving words like `c_int` in the language.
- [`@alignOf` for all types (#32080)](https://codeberg.org/ziglang/zig/issues/32080) - accepted: `@alignOf` would work for every type, returning 1 for vacuous and comptime-only types.
- [`align(1)` on wasm functions (#37302)](https://codeberg.org/ziglang/zig/issues/37302) - the core team agreed to allow it, and the fix landed in [PR #37386](https://codeberg.org/ziglang/zig/pulls/37386).
- [Fewer inline switch instantiations (#36696)](https://codeberg.org/ziglang/zig/issues/36696) - accepted: an inline switch prong that does not capture the tag would be instantiated once per payload type.
- [Lazy dependency fetching in the build system](https://codeberg.org/ziglang/zig/pulls/37177) - the build now fetches pending lazy dependencies and retries when an artifact is not found, with [a guard against infinite retry loops](https://codeberg.org/ziglang/zig/pulls/37391).
- [Naked package metadata](https://ziglang.org/devlog/2026/#2026-10-20) - dependencies that have no `build.zig.zon` of their own can now declare `version` and `paths` next to the URL, which gives them a readable package hash and filters out unwanted files.
